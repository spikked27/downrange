# Alpha 1 acceptance scope

The milestone is a cohesive private self-hosted application, not a certified forecast service.

## Required product path

A user can install/update from the Unraid GUI without recreating appdata; log in with the existing account; save locations anywhere with valid coordinates/timezone; inspect schedules and labeled source quality; open an observer-local sky/time view; configure obstruction angles; and opt into appropriate reminders. Source failures must remain visible and not become a claimed invisible launch. Model and data changes must not silently replay sent notifications.

## Required implementation checks

Automated geometry and input validation, account isolation, source identity/date/freshness checks, cache/quota boundaries, notification eligibility/deduplication, real HTTP desktop/mobile interaction, and persistent-data replacement from published predecessor images. PWA checks cover service-worker install and offline shell without private API caching. Synthetic tests are not evidence of real-world forecast accuracy or actual phone delivery.

## Explicitly outside this first alpha

Universal source-format ingestion; exact guidance for every vehicle; real-time liftoff confirmation; full terrain/obstacle survey; apparent plume rendering; calibrated brightness or viewing percentages; line-of-sight cloud analysis; guaranteed nighttime/daytime/later-burn coverage; background phone location; app-store packaging; public multi-tenant security audit. An incomplete source may still support a useful estimate, but must not be relabeled as a known mission path.

## Follow-on validation priorities

Record prediction inputs and compare them against documented real sighting times/directions; add non-Falcon ascent families with primary provenance; test source retirement/scrub/schedule transitions under actual feeds; verify phone delivery under the user's HTTPS setup. Revisit weather gating only with a model that does not confuse cloud cover at home with the whole viewing ray.
